# P6-06 volume portability and failure behavior

## What a move is allowed to be

Every volume declares a portability tier, and `plan_move` decides — before anything is
quiesced, copied, or started — whether a move is possible and what it would take. A
refusal names the volume that is in the way.

| Tier | Within a provider | Across providers |
|---|---|---|
| `ephemeral` | recreate | recreate |
| `provider_local` | the provider's snapshot | **refused** |
| `portable_offline` | quiesced offline copy | quiesced offline copy, if a snapshot format is declared |
| `shared_external` | reattach | reattach |

The plan is the strongest requirement any one volume imposes: a single
`portable_offline` volume among ephemeral ones still means a quiesced copy. A move
between CPU architectures is refused outright, even for a stateless workload, because
its image is built for one.

## The refusal is the feature

The failure this prevents is a stateful workload silently recreated as an empty one
somewhere else, reported as a successful migration. `recreation_is_lossless` exists so
a caller about to recreate a workload asks first; `false` means recreation loses a
`provider_local` or `portable_offline` volume and must be an operator's explicit
decision, not a reconciler's.

Legacy volumes begin as `provider_local`: the most restrictive tier that still allows a
move. An unproven volume is never quietly treated as portable.

## Order, and the irreversible point

`docs/operations/stateful-workload-moves.md` carries the offline-copy order — quiesce,
snapshot, checksum, copy, restore, verify, start — and names starting the target as the
irreversible point. Source and target are never writable at once. Before that point,
rollback is unfencing the source; after it, rollback is a new migration in the other
direction, never an unfenced restart, which would leave two writers and nothing to
reconcile them with.

## Failure behavior, proven

| Scenario | Where it is proven |
|---|---|
| A worker is cordoned: placement stops, running work is untouched | P6-03 `a_worker_is_cordoned_drained_and_returned_without_touching_identity`, live on Nomad |
| A worker is drained: work leaves, identity is unchanged | the same test |
| A cancelled drain does not return the worker to service | the same test |
| A workload dies under the scheduler: observed, then restarted as itself | P6-03 `a_lost_workload_is_observed_and_restarted_as_itself`, which removes the container the way a worker's kernel would |
| A control replica is lost: singleton work moves, fenced | P6-03A `live_singleton_work_happens_on_one_replica_at_a_time` and the eight-replica race, live on PostgreSQL |
| A replica is paused or partitioned from the database | P6-03A: it drops its lease rather than assume it still holds one, and its old token is refused at the destination |

## Open, and owned

- **Executing a move** — the quiesce, snapshot, copy, restore, verify sequence — needs a
  provider that can snapshot. The Nomad backend refuses snapshots today (P6-04) and the
  agent needs a KVM-capable host (P6-05). The rules and the order are fixed here so that
  when a provider can do it, it does it in the right sequence.
- **`ModalVolume` adoption** stays an operator action against the Phase 3 export
  inventory; the volumes are `provider_local` and are never orphaned (ADR 0022).
- **Clock-skew chaos** beyond what the coordination suite covers belongs with the
  Phase 9 load and chaos suites (plan 08).
