# P5-01 VMM contract, state machines, generation rules, and native parity matrix

## Requirement and ownership

P5-01 freezes the node-to-VMM boundary before any code moves (RL-013). It covers:
- the HTTP contract (A501);
- the workload and operation state machines (A502);
- the desired and observed generation and conflict rules (A503);
- the native behavior parity matrix (A505).

It blocks P5-02 through P5-06.

## Delivered

- **A501** `contracts/vmm/openapi.json` (OpenAPI 3.1, validated): 28 paths. The plan's
  list plus invocations, HTTP forwarding, files, builds, snapshots and restore,
  endpoints, proof verification, a terminal, and a global event stream (ADR 0029).
- **A502/A503**:
  - `aseman-domain::vmm` (pure): desired and operation transitions, generation
    compare-and-set, command freshness, observation ordering, one-step
    reconciliation with adoption, and capability checks;
  - `contracts/vmm/states.json`, the published table.
- **Wire types** `aseman-contracts::vmm`, including problem codes with fixed statuses,
  retryability, and the `LifecycleError` mapping.
- **A505**:
  - `contracts/vmm/native-parity.json`: all 27 A006 runtime operations and all 46
    `IVmm` methods mapped to an A501 operation, the node, the backend, the guest
    gateway, or a reasoned removal;
  - `scripts/generate_vmm_parity.py`, which renders
    `docs/generated/vmm-native-parity.{json,md}` with the capabilities the native
    backend must declare per runtime. It runs in the gate.
