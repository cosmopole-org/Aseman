# P6-02 compact and clustered topology

## What this is

`contracts/deploy/topology.json` names the three deployment profiles, every service, the
port each listens on, who may reach it, what it presents, and what privileges it holds.
`docs/operations/topology.md` is the operator's version of the same thing.

The invariant the whole artifact exists to protect: **one Aseman node is one federation
identity**. Adding or removing a worker, losing or replacing a control replica, and
switching the VMM backend all leave the node ID and its signing-key lineage alone, and a
replica address is never published as node identity (ADR 0013).

## Profiles

| Profile | Aseman replicas | Nomad servers | Workers | PostgreSQL |
|---|---|---|---|---|
| compact | 1 | 1 (also a client) | 1 | local |
| cluster | 3+ across failure domains | 3 or 5 | 1+, added and removed freely | external or HA |
| host | — | — | agents and clients on the host | — |

The compact profile's single replica still takes the coordination lease before singleton
work. That is deliberate: it is why a compact deployment can grow into a cluster without
changing how anything is fenced.

The replica count needs no quorum, because PostgreSQL owns application state and
coordination rather than a replica vote. Nomad's Raft quorum is a separate thing and is
three or five servers.

The host profile exists because Firecracker needs `/dev/kvm`, tap devices, and cgroup
control, and those stay on the host and out of every other service (ADR 0010).

## Checked, not just written

`scripts/check_deploy_topology.py` runs in `cargo xtask fast` and asserts the parts of
the contract the code actually decides:

| Claim | How it is checked |
|---|---|
| Every deployed service is in the contract, and nothing else is | the service list against the manifests that build them |
| The A504 listener is loopback-only | both backend binaries are read for the `is_loopback()` refusal |
| The published guest path is the one served | the contract's path against `CALLS_PATH` in `aseman-contracts` |
| A service claiming no privileges holds none | `apps/aseman-node/src` and `apps/aseman-vmm/src` are scanned for the Docker socket and `/dev/kvm` |
| The bring-up order names real services | against the service list |

The last one has immediate teeth: it is what keeps the Docker gateway from drifting back
into the node after P5-06 moved it to the backend.

## Tokens and separation

The Nomad token the backend holds is scoped to the `aseman` namespace and to job
submission and reading, allocation lifecycle, logs, and the allocation filesystem. It
carries no `operator`, `acl`, `agent-write`, or `node-write` capability, so a stolen
backend token cannot reconfigure the cluster or read another namespace's jobs.

The VMM CA and the Nomad CA are separate: a compromise of one does not admit the other.

Workers and workloads never reach PostgreSQL. Guest data is reached only through the
node's signed guest API (ADR 0001, A405).

## Open, and owned

- **The replicated control plane itself** — the `CoordinationPort`, its fenced leases,
  and failover — is P6-03A.
- **Enroll, cordon, drain, and loss recovery** are P6-03.
- **The worker agent's protocol and privilege model** are P6-05 (A603).
- **Compose and systemd profile files** follow the bootstrap work in Phase 9 (A007,
  plan 08); this unit fixes what they must produce.
