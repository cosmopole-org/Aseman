# P7-06 serve the public HTTP contract

## Obligation

- **Requirement:** R07, HTTP as the default public protocol.
- **Artifact:** A701's generated OpenAPI, with A401 authentication and A402 action
  metadata; A702/A703 remain separate module/listener work.
- **Accepted ADRs:** 0003 (versioned protocol boundary), 0004 (legacy adapters stay at
  the edge), 0008 (one fail-closed policy path), and 0009 (canonical signed proofs).
- **Owner:** network/node-shell.
- **Removal rows:** RL-004 and RL-009 gain replacement-edge evidence. RL-008 remains
  blocked on serving subscriptions, and RL-010 on the federation HTTP provider. None
  is deleted by this work unit.

## Delivered increment

`aseman-public-http` is the hardened transport boundary for all 76 operations in the
generated contract. It rejects routes absent from that contract, including the
policy-withheld `/creatures/login`, before application code; parses exactly one session
or A401 proof; requires shaped idempotency keys on mutations; emits request IDs and RFC
9457 problems; and applies body, rate, concurrency, duration, CORS, TLS, and bounded
connection-drain controls.

The edge calls one `PublicActionService`. `aseman-application::public_action`
(`ServePublicAction`) composes that contract's one atomic path: A401 authentication
(proof via `AuthenticateProof`, or a session via the `SessionDirectory` port), A402
authorization through the same `Authorize` use case and audit record as every other
surface, execution through the `ActionExecutor` seam, and durable idempotency
(`PublicActionIdempotency`) for mutations. The transport does not call a legacy
`ISecureAction`: doing so would treat A401 material as a legacy packet signature and
silently create a second security path.

`aseman-public-service` (`modules/public-service`) binds the transport trait to the
composed use case and translates application failures into the RFC 9457 problems the
transport already emits. `aseman-config::PublicHttpListenerConfig` types the listener
(`ASEMAN_PUBLIC_HTTP_*`) so a node process can construct it without a bespoke
environment reader.

The durable idempotency port is real: `aseman-storage-postgres` owns
`aseman_core.public_idempotency` (migration `0010_public_idempotency.sql`), one
digest-bound claim per (subject, key), and implements `PublicActionIdempotency` over
it. The port's conformance suite (`aseman-ports::conformance::public_action`) and the
full composed service run against live PostgreSQL (`live_public_action.rs`): first use
claims, a retry replays the recorded outcome, a different digest is a mismatch, an
unfinished claim is in progress, and a mutation retry executes exactly once.

## Characterization and negative evidence

- `cargo test -p aseman-application public_action`: proof authentication, session
  resolution, misbound-proof refusal, denied-action audit with no effect, replay
  refusal, one-run-then-replay idempotency, mismatch and in-flight refusal, and reads
  needing no key.
- `cargo test -p aseman-public-service`: the composed service through the transport
  trait returns 200 bodies, maps denials to 403 problems, and replays a mutation
  retry without re-executing.
- `cargo test -p aseman-storage-postgres --test live_public_action`: the durable
  store passes its port conformance suite and the composed service replays a retry
  against live PostgreSQL (`ASEMAN_TEST_POSTGRES_URL`; skips without it).
- `aseman-public-http` tests prove the route count and withheld route, contract
  metadata forwarding, mutation idempotency requirement, fail-closed authentication
  ambiguity, body and JSON limits, unknown-route refusal, and CORS refusal before the
  application service.

## Migration and rollback

Composition binds `PublicActionService` to the canonical authenticated application
gateway. A production node supplies the ports (`KeyDirectory`, `ReplayGuard`,
`SessionDirectory`, `IdentityVerifier`, `ClockPort`, policy, grants, decision audit,
durable idempotency, and an `ActionExecutor` over migrated use cases), places this
listener beside the legacy TCP/WebSocket listeners, compares parity, then makes HTTP
the advertised default. Rollback stops advertising this listener and routes clients to
the still-isolated ADR-0004 adapters. No application state or legacy listener is
changed by this increment.
