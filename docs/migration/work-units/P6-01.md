# P6-01 desired state as Nomad jobs

## What this is

`modules/vmm-backend/nomad` is a second A504 backend. It holds no Aseman state: it
turns a `WorkloadRecord` into a Nomad job and Nomad's allocation state back into an
Aseman observation. The node is unchanged — it speaks A501 to the VMM, which chooses
the backend.

Aseman does not bundle, mirror, or download Nomad (ADR 0002). The operator supplies a
cluster and the backend is pointed at it; the live test skips when none answers.

## The mapping

`contracts/vmm/nomad/mapping.json` is the contract, and `src/job/tests.rs` reads that
file so the code cannot drift from it silently.

| Aseman | Nomad |
|---|---|
| workload UUID | job ID `aseman-{workload}`, so a register is idempotent and a workload can never place twice |
| desired state | the group's count: 1 running, 0 otherwise. A stop keeps the job, so a restart keeps the workload's identity and history |
| desired generation | job meta `aseman.generation`, which is what an observation reports — never the caller's number, so a stale allocation is never reported as current |
| resources | CPU MHz (one core = 1000) and MemoryMB, at Nomad's floors |
| ingress ports | group dynamic ports by label; an http port is also a Nomad service |
| egress policy | the worker's CNI policy, not the job spec: a job spec cannot express "deny" |
| delete | `stop?purge=true`; purging an unknown job is success |
| pause | refused. Nomad has no allocation-level pause and stopping the group is not one |

## What it refuses

A backend that pretends is worse than one that says no, so the mapping refuses rather
than approximates: pause, snapshot and restore, exec, execution proofs, writing files
into a running allocation, and building an image. Each is either another component's
(the worker agent, P6-05) or another step's (the image is built before registration).

Nomad's `cat` answers a missing path with a plain-text message and a *success* status.
The client stats a path before reading it, so an error message is never served to a
workload as file content.

`raw_exec` is never used, in any mode (plan 04). The mapping sets no privileged flag,
no host network, no host PID namespace, and no host bind mount; a test asserts this,
because these are the fields that would silently hand a workload the host.

## Security

- The workload credential never enters the job spec. Nomad stores job specifications in
  plain text and shows them to anyone who can read the job, so the credential goes to
  the task's secrets directory (ADR 0019, ADR 0023). A test asserts it is absent.
- Every workload runs in `bridge` mode, in its own network namespace.
- The backend's Nomad token is namespace-scoped; it has no operator or ACL rights.
- Nomad workload identity proves which allocation is calling; it authorizes no Aseman
  operation. The workload still signs its guest-API calls with its Aseman credential
  (A405).

## Baseline

`environment_reads` rises from 3 to 4: `ASEMAN_TEST_NOMAD_ENDPOINT`, read in
`aseman-config`, which is the one crate that parses the environment (AGENTS.md). The
ratchet's intent — no environment read outside the config crate — still holds; all four
reads are there.

## Open, and owned

- **Runner images** for javascript, wasm, elpian, and elpify are declared by the
  operator; the mapping never invents one. P6-04 defines them.
- **QEMU and Firecracker** are P6-04 and P6-05; Firecracker's host work is the worker
  agent's (ADR 0010).
- **Egress enforcement** needs the worker's CNI policy: P6-04.
- **Volumes** are P6-06 (ADR 0011).
