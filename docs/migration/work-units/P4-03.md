# P4-03 capability issuance, attenuation, expiry, explanation, and descendant revocation

## Delivered

- **Domain** (`aseman-domain::capability`):
  - grants and resource selectors;
  - chain validity: live, linked, attenuating, bounded;
  - `delegate`, by intersection only;
  - `revocation_closure`.
  - Tests cover tampered chains, depth exhaustion, and descendant revocation, plus a
    2,000-round randomized no-amplification property test.
- **Evaluator:** `granted` holds for a chain that authorizes the request, and the
  decision's `grant_chain` explains it.
- **Registry:** `capability.issue`, `capability.delegate`, and `capability.revoke`, over
  a new `grant` resource type.
- **Port:** `GrantStore`, with a conformance suite.
- **Application** (`aseman-application::capability`):
  - `Authorize` loads chains, bounded to 16 links, then decides.
  - `IssueGrant` checks a root grant against the registry.
  - `DelegateGrant`.
  - `RevokeGrant` returns the voided subtree for re-evaluation.
  - `grant_is_live`.
  - `SetDesiredWorkloadState` now authorizes through `Authorize`, so grants count.
- **Storage:** `core.capability_grant` is redefined for the full grant model, with no
  subject relationship to `core.user`, because subjects are of every class. The new
  `0000_retire_obsolete.sql` runs before `0001` and drops the writerless first shape,
  and `node_keys`. Both are tested live against a database seeded with the old shapes.
  `CapsuleGrantStore` passes conformance live.
- **Fixtures:** six grant cases in A404 (live chain, revoked root, expired grant,
  foreign resource, tampered widening, wrong subject class). The reference provider
  reproduces all 30 cases.
