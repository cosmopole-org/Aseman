# P9-05 canonical entry points and documentation roots

## Obligation

- **Requirements:** R19, R20, R21, R22, R23, and R24.
- **Artifacts:** A901, A903, A906, A1001, and A1005.
- **Accepted ADR:** 0004 controls the old executable names and prevents premature
  deletion.
- **Removal rows:** RL-001, RL-015, RL-016, and RL-017.

## Delivered increment

`apps/aseman-node` and `apps/asemanctl` are the canonical executable composition roots.
The CLI implementation and warning alias binary live together under `apps/asemanctl`.
The node implementation, key generator, diagnostics, and warning alias binaries live
together under `apps/aseman-node`. The former `cmd/` and `node/` proxy packages are
deleted, so compatibility names do not create a second module or dependency boundary.

The compatibility client is consolidated at `apps/aseman-client`. All runtime
projects and the legacy
runtime SDK are under `modules/runtime`; old wiki material is explicitly archived at
`docs/legacy/caspar` behind the current documentation portal.

The canonical root documents, `docs/` portal, `deploy/`, and
`tests/evals/agent/` now exist. Creature-implementation guidance for every runtime
lives in `docs/development/creature-implementation.md`. The agent catalog names real
authority files and verification
commands, and `check_agent_evals.py` runs in the fast gate so a moved/deleted authority
cannot leave a plausible but stale answer behind.

The A906 release workflow no longer commits generated binaries into the repository. It
builds into a runner-temporary directory and publishes deterministic multi-architecture
archives with SPDX 2.3 SBOMs, SHA-256 checksums, and signed provenance/SBOM attestations.
`scripts/check_release_policy.py` binds that workflow to the release policy, Cargo
license metadata, full action commit pins, and RL-018's two-part deletion gate.

`crates/aseman-guest-sdk` is the canonical guest package. It constructs signed A405
calls only for registered operations and intentionally exposes no creature, database,
provider, namespace, or role selector. Its executable example is compiled in the gate.

`apps/aseman-meter` is now the separate metering process. It reads only typed meter
configuration, reaches A501 with mutual TLS, persists raw samples and intervals, and
settles through the PostgreSQL pricing/ledger ports. `--once` provides an operational
probe while the default process repeats at the configured interval.

## Migration and rollback

Packaging publishes the Aseman binaries first and retains the Caspar names during ADR
0004's window. Rollback invokes the same canonical implementations through warning
aliases under the old names; there is no duplicated state or command implementation.
The global structured wrapper and generated public clients complete the repository-owned
command/client replacement before those aliases can be considered for deletion.
