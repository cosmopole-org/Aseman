# P5-04 host calls through the authenticated guest API

## Requirement and ownership

"Guest host calls move to the authenticated Aseman guest API" (plan 04), and the VMM
loses every other route into the node.

## Delivered

- **Credential** (`aseman-contracts::guest_api`): a workload's Ed25519 seed, key ID,
  epoch, audience, and its node's guest API URL, encoded as the write-only
  `bootstrap.credential` of A501. It never appears in `Debug` output, and decoding
  checks that the key ID matches the seed.
- **Signing**: a request signs the A402 action its call is registered as, with the op
  or digest as the resource and the exact body in the digest. Signer and verifier
  derive the action from the same registry (`call_action`).
- **Use cases** (`aseman-application::guest_call`):
  - `ServeGuestCall`: A401 proof, workload subject, the signed action, the workload
    record (not deleted), then its creature and program from the trusted records.
  - `ProvisionWorkload`: record, register the key, ask the VMM to create; repeatable
    after a crash (the record stays, a new key epoch replaces the old, the VMM
    deduplicates by idempotency key).
- **Transport** (`modules/guest-http`): the node's TLS listener and the backend's
  client, which speaks https only.
- **Node** (`node/src/shell/workloads.rs`): the guest API implementation over the
  node's ordinary authorized host-call path, workload provisioning, lifecycle, signal
  invocations, ingress forwarding, and the `vmm-handoff` command.
- **`stateOp`** (`unified-host-call stateOp`, `guest_data.access`): a remote runtime's
  creature-scoped key/value state, confined to the caller's own creature (ADR 0021).
- Artifacts are served only to the workload's own entity, and only when the bytes
  match the requested digest.

## Verification

| Check | Evidence |
|---|---|
| The credential round-trips, signs what the node verifies, and never prints its key | `aseman-contracts` `a_credential_round_trips_signs_and_never_prints_its_key` |
| A proof for another operation, a replay, and a deleted workload are refused | `aseman-application` `guest_calls_run_as_the_resolved_workload_only` |
| Provisioning is safe to repeat | `provisioning_records_registers_and_creates_and_is_safe_to_repeat` |
| Over real TLS: the node serves a backend's call, refuses another workload's key, never uses plain http | `aseman-guest-http` `a_backend_calls_the_node_as_its_workload` |
| A real program's state calls arrive signed as its workload | `aseman-vmm-backend-native` `live_native` |

## Rollback

The guest API listens only when `ASEMAN_VMM_ENDPOINT` is configured.
