# P4-01 identities, trust roots, key rotation, and revocation

## Requirement and ownership

P4-01 implements A401 under ADR 0009. The work is:
- typed identities with separate keys per class and purpose;
- the canonical signed structure, and a verifier that enforces freshness, audience,
  replay, epochs, and revocation;
- explicit federation trust roots.

It blocks P4-04, the signed guest gateway that fixes LD-14 and LD-24, and P7
federation.

## Delivered

- **A401 contract** (`contracts/security/identity-v1.md`) with generated vectors
  (`contracts/security/vectors/identity-v1.json`): a valid proof plus nine negative
  cases, each with its error code.
- **Domain** (`aseman-domain::identity`, pure):
  - subjects with one canonical text
  - key purposes and the contexts each may sign
  - stable authentication error codes
  - freshness windows and replay retention
  - epoch acceptance: the current epoch or the immediately prior one within the
    overlap; revocation overrides; legacy keys never sign authority
- **Contracts** (`aseman-contracts::identity`):
  - versioned multicodec keys, with Ed25519 canonical and legacy RSA verifying
  - multibase text and multihash key IDs
  - the signing input and the strict JSON proof
  - Ed25519 signing, for nodes, SDKs, and vectors
  - legacy RSA-PSS verification

- **Ports** (`aseman-ports`):
  - `KeyDirectory`: by key ID, by subject and purpose; register; retire and revoke
    keep the earliest time.
  - `ReplayGuard`: atomically records (key ID, nonce).
  - `IdentityVerifier`: signature check and body digest.
  - Conformance suites for the directory and the guard.
- **Application:** `AuthenticateProof` applies A401 steps 4-12 in order. Its tests show:
  - each check rejects with its own code;
  - no rejected proof consumes a nonce;
  - a valid proof authenticates once;
  - revoked keys and an unavailable directory are refused.
- **Adapters:**
  - `aseman-identity-native` (`NativeIdentityVerifier`): the committed A401 vector
    authenticates end to end through the use case.
  - `aseman-capsule::identity` (`CapsuleKeyDirectory`, `core.identity_key`)
    and the PostgreSQL `ReplayGuard`: both pass conformance on live PostgreSQL.
- **Schema:** `core.identity_key` replaces `core.node_key`, which had no writer.
  Migration `0005` drops `node_keys` and adds `replay_nonces`. The migration is
  idempotent and verified live.

- **Key lifecycle** (`aseman-application::identity`):
  - `RotateKey` registers the next epoch and retires the current one. A key that is
    refused retires nothing.
  - `RevokeKey`.
  - `IssueChallenge` issues one-time nonces for at most five minutes.
  - `EnrollCanonicalKey` implements the ADR 0019 cutover prerequisite. A legacy RSA
    identity answers a challenge with its legacy key, and the signature binds the new
    Ed25519 key. The legacy key becomes epoch 0, already retired, so it verifies only
    through the overlap and never signs authority. Enrollment happens once.
  - `AcceptIntroduction`: an enrolled root registers a node's descriptor key.
    Introduced nodes cannot introduce.
- **Challenges:** the `ChallengeStore` port, with the PostgreSQL adapter consuming a
  challenge by deleting it. It passes conformance live.
- **Vectors:** the canonical introduction bytes are part of the contract vectors.

## Wiring

These use cases have no transport yet. They are wired by:
- P4-04: guest gateway authentication with workload keys.
- P7-01: the public API, which carries enrollment, rotation, and revocation for
  creatures and users.
- P7-02 and P7-03: introductions and revocation statements between nodes.

Who may rotate, revoke, or enroll roots is decided by the A402 action registry and the
policy engine (P4-02).
