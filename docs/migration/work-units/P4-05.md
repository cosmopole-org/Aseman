# P4-05 enforce every registered action; property and adversarial tests

## Enforcement

`node/src/shell/authority.rs` is the one decision point for both entry surfaces:
- every guest host call (`unified-host-call {op}`), after the caller is identified
  from the node-stamped packet;
- every signed shell action (`signed-shell-action {path}`, in `build_secure_action`),
  after the signature is verified.

Each decision:
- maps the surface to its A402 action; an unregistered surface is refused;
- resolves facts server-side from the target, relative to the caller's principal (the
  user owning the caller):
  - `owner` and `same_creature` when the target belongs to that principal;
  - `self` when the target is the caller;
  - store permissions from membership;
  - `node_admin` for the legacy root;
- names the resource, for example the egress destination host, so grants match only
  their resource;
- loads the caller's grant chains when the node runs on PostgreSQL;
- decides with the reference provider (`aseman-policy-native`);
- appends the decision to the actor's `audit.event` stream on PostgreSQL
  (`shell/audit.rs`), from a writer on its own connection with backpressure and no
  drops.

Shadow mode (decided, audited, not refused) is limited to three actions, each with an
end condition:
- `network.egress`, until egress grants are issued (A406);
- `identity.session.login_by_email`, until RL-019 removes it;
- `creature.list`, until P7-01 defines discovery scopes.

## Phase 4 gate evidence

| Gate requirement | Evidence |
|---|---|
| No authority amplification | Randomized delegation property test (2,000 rounds, `aseman-domain` capability); tampered-chain refusals; descendant revocation; A404 grant fixtures reproduced by the provider; `granted` cannot be asserted as a fact |
| No cross-creature database connection, catalog, data, enumeration, cursor/cache reuse, or pooled-role leakage | A306 live isolation test (two databases and roles, catalog absence, direct-login denial, role-contamination detection, pool reset and retirement); live gateway test (two creatures write the same key and each reads its own); a tampered binding cannot route (provider name re-derivation); live guest data routing refuses unbound creatures |
| No workload identity spoofing | LD-27 tests (identity only from the packet; the docker gateway refuses unidentified containers); runtimes and elpian send the node-stamped envelope; the gateway resolves workload, program, creature, and binding server-side, and a crossed program fails closed |
| No signature spoofing | A401 vectors with nine negative cases; `AuthenticateProof` tests (forged, replayed, impersonating, revoked, other audience, expired); the nonce is consumed only after the signature verifies |
| No database, namespace, or role spoofing | Bindings come only from the trusted catalog; the provider re-derives names; guest state is confined to the creature (`guest_state` tests); namespaces are separate (guest KV conformance) |
| Every registered action enforced | Every host call and signed action passes the decision point; enforcement tests cover creature, store, access, program, workload, and resource-store CRUD, guest data, removed and unknown calls, signed actions per signer, anonymous callers, and root-only minting |
