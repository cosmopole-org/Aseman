# P7-05 legacy transports as framing adapters

## The claim, and why it is checked rather than asserted

The Phase 7 gate requires that the legacy TCP and WebSocket transports "contain framing
only and share one session/application path". That is a property of the code, and a
property nobody checks is a property that decays: the natural way for a transport to
grow is by answering one more thing for itself.

`scripts/check_legacy_transports.py` runs in `cargo xtask fast` and fails when either
adapter does its own action lookup, authorization, storage access, session
classification, or rate-limit policy, or stops handing inbound bodies to the shared
session path.

An adapter may frame bytes, manage its own sockets, and delegate. Nothing else.

## The shared path

`apps/aseman-node/src/drivers/network/client/session.rs` owns authentication, rate-limit identity,
action lookup and dispatch, response codes, listener attachment, and gateway
subscription effects. `tcp.rs` and `ws.rs` each hand their decoded body to
`session::process_inbound` and write back what comes out.

So the three transports — HTTP, TCP, WebSocket — are three framings of the same
actions, which is what makes the public contract (A701) the whole API rather than one of
several.

## Verification

Verified by tampering: adding a single `classify_session_route` call to `tcp.rs` makes
the check fail and name the file, the line, and what it did. Removing it makes the check
pass again.

Comments are ignored, so a line explaining why something is *not* done in the adapter
does not trip it.

## Open, and owned

- **Retiring the legacy transports** is ADR 0004's compatibility window and the removal
  ledger's, not this unit's: while they exist, they must stay framing.
- **The HTTP framing** of the same actions is the node shell's work against A701.
