# P7-07 canonical gateway and listener handoff contracts

## Obligation

- **Requirement:** R07.
- **Artifacts:** A702 and A703.
- **Accepted ADRs:** 0003, 0004, 0008, and 0009.
- **Owner:** network/node-shell.
- **Removal rows:** RL-009 and RL-010. This work does not expire either legacy wire
  adapter.

## Delivered

A702 is the versioned protobuf boundary between network modules and the single public
application gateway. It carries the common request metadata, forwards exactly one proof
or session credential without granting authority, binds the registry action and class,
and defines unary actions, bounded resumable event streams, interactive terminal
streams, cancellation, negotiation, and structured errors. The checked compatibility
catalog freezes every v1 field number and its fail-closed rules.

A703 is both a normative contract and an executable pure state machine. A candidate is
staged and proven ready before atomic activation; the previous generation drains while
new work reaches exactly one active generation. Candidate failure leaves active traffic
alone, post-activation failure rolls back to the still-draining generation, stale
generations fail, and completed drains retire their listener. Four tests cover those
transitions.

## Migration and rollback

HTTP/SSE/WebSocket and federation modules implement A702, while the node owns A703.
Legacy TCP/WebSocket/federation adapters remain available through ADR 0004. Rollback
activates the prior draining generation; it does not restore a second application
authorization path.

## Runtime composition

`modules/network/gateway` now serves the generated A702 bindings over a loopback-only
gRPC endpoint and translates unary, durable replay subscription, terminal, negotiation,
and cancellation semantics into the same application services as public HTTP. Its
`GatewayListenerBroker` is the live A703 runtime: candidates bind before activation,
generations are committed through the domain state machine, predecessors remain
available for bounded drain/rollback, and failed candidates never disturb active
traffic. Deployed handoff/rollback observation remains a rollout item, not missing
repository implementation.
