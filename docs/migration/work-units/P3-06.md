# P3-06 dual write, semantic comparison, cutover, and rollback

## Requirement and ownership

P3-06 implements A309 (the dual-write, read-compare, cutover, and rollback parts of the
protocol) under ADRs 0005, 0006, 0007, and 0016–0025. RL-005 owns the legacy storage
path, and its deletion stays gated on a production cutover plus its deletion gate.

## Delivered (A309 ACCEPTED)

- **Domain** (`aseman-domain::storage_migration`, pure):
  - The ten-step state machine with phase guards and monotonically increasing binding
    generations. Rollback raises the generation to fence stale writers, and a lost
    shadow write blocks the delta before cutover and forbids rollback after it.
  - `compare_records`: counts per kind, identities, semantic digests, and dangling
    references.
- **Ports:** `MigrationStateStore` (compare-and-swap), `MigrationRecordSource`, and
  `CanonicalRecordWriter`. Writers must fence old generations transactionally.
- **Application:** `StorageMigrationService`, which drives the steps against durable
  state, and `DualWriteRouter`, which writes the authority first, then shadows the
  write and records failures durably.
- **Contracts:**
  - `semantic_digest` covers what a record means and excludes the revision chain, so
    re-applied revisions still compare equal (ADR 0005).
  - `plan_delta` produces inserts, chained replacements, and tombstone revisions.
- **PostgreSQL provider:**
  - Writes, reads, queries, and snapshots every storage-class table the export emits.
    Previously only the core tables had a writer.
  - Enforces class checks and refuses updates of append-only kinds.
  - `put_fenced` runs the generation check in the same transaction as the write.
    `0003_migration_fence.sql` holds the fence, which only increases.
  - `snapshot_all` feeds the comparison.
  - The guest legacy KV importer writes into the creature's own database, into the
    reserved `_aseman_legacy_kv` table, with an owner check and idempotent replay.
- **Proof:** `tests/migration` runs the whole chain live on PostgreSQL 16: legacy
  snapshot, export, import, guest import, verify, a blocked delta, the applied delta,
  fenced cutover, and rollback.
- **Docs:** `contracts/migration/protocol.md` and
  `docs/operations/storage-migration-runbook.md`.

## Node rewiring (legacy provider wrap)

- `aseman-storage-legacy` now owns every legacy storage client:
  - `LegacyKvStore` with `RocksDbKvStore`: exact prefix scans by seek, atomic batches.
  - The process-wide RocksDB tuning and block cache (`tuning`).
  - `QuestDbTimeSeries`: the startup table repair, tag-validated signal SQL, and
    build logs. It uses the same `LegacySignalRow`/`LegacyBuildLogRow` types as the
    migration export.
- The node's core path names no RocksDB or QuestDB types: `KvDb` is
  `Arc<dyn LegacyKvStore>`, and `ts_db()` left the `IStorage` port. The rewired paths
  are `trx.rs`, `drivers/storage.rs`, cluster KV apply, telemetry, and `scan_vmdb`.
- Remaining in-node RocksDB users are Phase 3 gate exceptions with owners: the OpenRaft
  store (`drivers/cluster/store.rs`, RL-012 / ADR 0012) and the Hashgraph store
  (`hashgraph/rocks_store.rs`, RL-011 / ADR 0025, which moves into
  `modules/consensus/hashgraph` in P8). Both use the provider's shared tuning.
- Behavior is unchanged, including LD-10 (a swallowed commit failure), which is
  preserved as characterized.

## Store strangler (RL-004)

- **Use cases:** `/stores/signal`, `/stores/history`, `/stores/setAccess`, and
  `/stores/getAccess` call `aseman-application::store`. Legacy error strings are
  preserved. The capsule adapter (`aseman-capsule-repositories::store`) passes the same
  use cases live on PostgreSQL.
- **Membership:** every membership reader and writer goes through the `StoreAccess`
  port. The trx-only legacy adapter, `LegacyMembership`, owns the `onaccess`/`hasaccess`
  encodings, and `LegacyStorePorts` delegates to it. Rewired: the security guard, the
  signaler fan-out, WS/TCP session group joins, both VM run membership checks, the
  program bootstrap, creature signal permissions and deletion, federation membership
  mirroring, and the VM host calls (store create and delete, createAccess,
  deleteAccess, list, listMembers, creature delete).

    `model/store_ports.rs`, `model/access.rs`, comments, and the LD-12 test.

  `removing_a_member_everywhere_fixes_the_empty_legacy_walk`.
- **Inventory:** `generate_legacy_data_inventory.py` maps the shared `access_link_key`
  builder to its key family (`KEY_HELPERS`). Direct transaction accesses fell from 292
  to 273. The A308 manifest stays ACCEPTED with zero blocked rows.
- **LD-12 repair:** `audit_legacy_memberships` and `repair_legacy_memberships` in
  `aseman-storage-legacy` (ADR 0018 amendment, runbook prerequisite 6).
  - Removes, under an approved digest, only the links a missing store or a dangling

  - Reports LD-11 one-sided pairs and orphaned-creator stores for an operator
    decision.
  - Test: `membership_audit_repairs_ld12_residue_only_under_the_approved_digest`. After
    the repair and the operator decisions, the export accepts every link.

## Creature strangler (RL-004)

- **Ports:** `CreatureDirectory` (identity) and `CreatureBalances` (balance: `open`,
  `balance`, `set_balance`, `close`), plus the
  `aseman-domain::creature` values and the shared `legacy_page` window. The balance is
  separate because the target model keeps it in `finance.wallet`.
- **Use cases:** `aseman-application::creature` (create, get, list, update, delete,
  getByUsername, find). The rules and error texts are the legacy ones, except for
  LD-13.
- **Legacy adapter:** `LegacyCreatures` (node) keeps the `Creature` object, the
  `username` index, and the `balance` column exactly.
- **Capsule adapter:** `aseman-capsule-repositories::creature` writes what the A308
  export writes (`core.user` for humans, `core.creature`, `finance.wallet`,
  `core.legacy_identity`) in one transaction.
  - PostgreSQL gained `put_all` / `put_all_fenced` (up to 64 capsules; it advertises
    `transactions.multi_capsule`). `CapsuleStore` gained `put_all`.
  - Listing pages by keyset, and re-sorts by bytes wherever legacy order matters.
- **Conformance:** `aseman_ports::conformance::creature_directory` (feature
  `conformance`) runs on both adapters: `legacy_creatures_pass_the_directory_conformance_suite`
  in the node, and `live_creature_ports_pass_conformance_on_capsules` live on
  PostgreSQL. The live test also proves that `put_all` rolls back a partial write.
- **Rewired:** `/creatures/create`, `get`, `list`, `update`, `delete`, `meta`,
  `getByUsername`, `find`; `/machines/list`; the VM creature host calls (LD-14
  mitigation); the driver's username route lookup.
- **Documented differences after cutover:**
  - Public keys are stored canonically (contracts `legacy_keys`), so a non-standard
    PEM spelling reads back as the standard LF PEM, and a non-RSA key is refused.
  - A machine must be owned by a human user, as the A308 export requires.
  - `/creatures/create` resolves the type's opening balance before the username
    check, so a request that is wrong in both ways reports the unknown type first.
- **Export fix (A308):** a human without an email was exported with `email = ""`.
  Because `uq_users_email` is unique, the second such human would have made the import
  conflict. An absent email is now omitted (NULL). The live test creates email-less
  humans side by side.
- **Balances:** every balance read and write goes through `CreatureBalances` via the
  legacy `Account` helper. That covers `/creatures/transfer`, `mint`, `lockToken`,
  `consumeLock`, the 13 balance sites in `creature/finance.rs`, and the finance
  reconciliation audit. A write-back sets only the `balance` column; the old code
  re-pushed the whole record.
  - LD-13, finance: the `id.is_empty()` checks at these sites never fired. A credit to
    a missing creature re-pushed the record and created a partial Creature. Now the
    site's existing "not found" error fires, a write-back to a missing creature fails,
    and the audit reports a withdrawable counter that has no creature.
  - Test: `accounts_write_only_the_balance_and_never_create_ghost_creatures`.
- **Identity reads:** the remaining `Creature::pull` reads (VM host calls, proxy, chain,
  program actions, store signal, login, creature signal) and the `type`/`username`
  column reads in the guard, security driver, and signaler use the directory.
  `creature_or_empty` keeps legacy `pull` semantics: a missing creature reads as an
  empty record with its id.
  - LD-13, login: a stale `UserEmailToId` link is now dropped as the code intended.
- **Still direct:** finance ledger state (journals, withdrawable, debt, holds, payout
  counters), the creature type registry, metadata documents, sessions, email and
  private-key links, and the `ownerof` / `machinePrograms` relations. These belong to
  the finance-ledger, identity, and program slices.

## Creature metadata (RL-004)

- **Port:** `CreatureMetadata` (`MetadataKind::Creature` / `User`). Documents cross it
  as JSON object text; paths are legacy dotted paths under `metadata`.
- **Shared conversion:** `aseman-contracts::legacy_documents` (JSON to capsule value
  and back, digest, the ADR 0016 document fields, path lookup). The A308 export and
  the capsule adapter both use it.
- **Adapters:** the legacy adapter keeps the `json::CreatMeta` / `json::UserMeta`
  splats, clearing the tree before a replace so no stale child splat survives. The
  capsule adapter writes `core.creature_metadata` / `core.user_metadata`, revives a
  tombstone as the next revision, and returns only objects at a path, as legacy
  `get_json` does.
- **Conformance:** `aseman_ports::conformance::creature_metadata` on both adapters.
  The node test, and the live PostgreSQL test with a key unique in the target
  schema.
- **Rewired:** `/creatures/create`, `delete`, `meta`, the user extender fields
  (`getByUsername`, `find`), and the `/machines/list` profile.
- **Owner links (LD-16):** the legacy adapter derives `ownerof` on create, update, and
  delete. The pre-export repair (`repair_legacy_memberships`, audit digest v2) removes
  dangling and stale links and rebuilds missing ones.
- **Type registry:** `CreatureTypes` port (`Json::CreatureType` + `CreatureTypeExists`
  on legacy, `core.creature_type` on capsules), with conformance on both adapters.
  Built-in registration, the legacy human-balance migration, `resolve_initial_balance`,
  and `/creatures/types` use it.
- **Identity credentials** (sessions, email login links, custodial keys, secrets, login
  grants) stay legacy-authoritative until the P4 obligations of ADRs 0019/0023 are met
  (ADR 0026).

## Transaction atomicity (ADR 0026 prerequisite)

- LD-10: `ITrx::commit` returns write errors; a failed batch replicates nothing.
- LD-15: secured actions and the VM signal host call discard a failed action's writes,
  as the Go original did, and report a failed commit as the action's error
  (`ICore::modify_state_securly_checked`).
- Test: `a_failed_commit_is_reported`.

## Remaining

- **Deletion:** removing the legacy storage path requires a real deployment cutover and
  the RL-005 deletion gate (AGENTS: never delete before both gates pass).
- **CLI:** the `asemanctl storage migration …` operator surface is delivered by P9-01.
- **Strangler:** program, finance (including balance mutations), creature metadata and
  sessions, gateway, and federation state still read the transaction directly.
