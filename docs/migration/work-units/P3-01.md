# P3-01 capsule contract work record

## Requirement and artifacts

P3-01 implements A301–A304 under ADR 0005 (deterministic CBOR and integrity) and
ADR 0006 (per-kind consistency). RL-005 is the owning removal row. This slice changes
no current storage authority and therefore does not authorize deleting RocksDB,
QuestDB, keys, tables, or compatibility adapters.

## Implemented

- Portable envelope values with typed identity, class, owner, schema/revision,
  timestamps, previous digest, relationships, tombstone, and body semantics.
- Strict deterministic CBOR encoder/decoder with preferred integer/float widths,
  encoded-key ordering, definite lengths, UTF-8, finite floats, depth/item/byte limits,
  duplicate/trailing-byte rejection, and a checked version-1 byte vector.
- Domain-separated `sha2-256` integrity that excludes only the integrity field and all
  provider-private metadata; mutation and malformed revision/tombstone tests fail.
- Closed JSON projections for envelopes, definitions, queries, capabilities, and the
  core registry.
- Bounded typed query predicates, projections, sorts, aggregates, relationship
  traversal declarations, and signed cursor binding values.
- Exact dotted provider capability wire values and negotiation that reports missing
  consistency, index, relationship, and guest-isolation guarantees without weakening.
- Complete initial core logical field/relationship/index/retention registry, unique
  core-kind/native-table mapping, and generated capsule catalog.
- Frozen valid/invalid query, query-error, capability, deterministic-CBOR, and integrity
  vectors consumed by the reusable storage provider conformance kit (A310).
- Provider-harness cases for exact round trips, tamper rejection, compare-and-set
  revisions, typed bounded queries, tombstones, and fail-closed capability negotiation.

## Migration and rollback

These contracts are additive and not read by the current legacy storage path. Rollback
removes the new contract crate module/catalog while leaving physical data untouched.
Future provider writes may begin only after the full registry and conformance gates pass.

## Acceptance evidence

`cargo xtask fast` verifies the contract crate, generated catalog, characterization
fixtures, and `aseman-storage-conformance` under warning-denied Clippy. P3-01 is
additive; RL-005 remains open until later Phase 3 replacement and deletion gates pass.
