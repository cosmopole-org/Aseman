# P6-05 the worker agent and Firecracker

## Why the agent exists

Running a microVM needs `/dev/kvm`, tap devices, cgroups, and a jailer. Something must
hold that privilege. The choice is where: spread across the node and the scheduler, or
concentrated in one small component that can be audited and disabled per host.

ADR 0010 chose the second, and rejected a privileged Nomad task-driver plugin — that
would tie the only Firecracker implementation to Nomad's plugin ABI and put Aseman's
privilege inside the scheduler. Nomad schedules an unprivileged runner task; the backend
asks the local agent to do the host work for that allocation.

## The shape of the trust

Mutual TLS says **which component** is calling. A signed, short-lived **grant** says
**what it may do**: one allocation, one declared machine profile, a set of operations, a
deadline. A caller with a valid certificate and no grant can do nothing at all.

A grant never carries a machine specification. It names a profile the administrator
declared on that host, which is what stops a compromised VMM from asking for a microVM
with the host's disk attached.

## What it does not expose

No shell. No command of the caller's choosing. No arbitrary path — every path derives
from the agent's own allocation root, and a name that could escape it is **refused, not
normalized**, because cleaning it up turns an attack into a silent success somewhere
unexpected. No arbitrary device. No raw Firecracker API: the agent speaks to
Firecracker, callers speak to the agent.

## Pause means pause

`MachineState::allows` refuses a pause of a machine that is not running and a resume of
one that is not paused. The API's pause is the runtime's pause, through Firecracker's
`PATCH /vm`; it may never degrade to a stop and a start (A604). A degraded pause that
reported success would be worse than a refusal — the caller would believe memory was
preserved.

A machine whose process died is `Failed`, and `Failed` does not allow a start. A dead
machine is looked at, not silently restarted.

## Honest about what this host cannot do

This host has no `/dev/kvm`, so no microVM boots on it. That is not a reason to test
against a double. Firecracker's API socket, its configuration handling, and its
refusals are all real here, and the property that matters most is exactly the one this
host can prove: **the agent reports a host that cannot boot rather than pretending it
did.** `capability()` refuses before anything is written, and a failed boot carries
Firecracker's own words.

## Verification

| Requirement (A603) | Evidence |
|---|---|
| A grant covers one allocation and nothing else | `a_grant_covers_one_allocation_and_no_other`, and live in `a_grant_that_does_not_cover_the_request_is_refused_before_the_host_is_touched` |
| An expired grant is refused with no tolerance | `an_expired_grant_is_refused_with_no_tolerance`, and live |
| A grant allows only the operations it names | `a_grant_allows_only_what_it_names`, and live |
| A path that escapes the allocation root is refused | `an_allocation_name_that_could_escape_the_root_is_refused`, with seven hostile names |
| Pause is the runtime's pause | `a_pause_is_the_runtimes_pause_and_never_a_stop` |
| A host without KVM refuses the work | `a_host_without_kvm_refuses_the_work_instead_of_accepting_it`: the refusal leaves no machine behind |
| The capability can be disabled independently | `a_disabled_host_refuses_before_it_looks_at_anything_else` |
| Firecracker is really driven through its API | `firecracker_is_configured_through_its_api_and_never_lies_about_booting`: a real process, a real API socket at the path the agent chose, a real machine configuration, and a boot that fails with a real reason |
| A deleted machine leaves nothing behind | the same test asserts the directory is gone |

## Open, and owned

- **The agent's mTLS listener and grant signature check** are wired when the backend
  calls it; the contract fixes both, and `authorize` is the decision they enforce.
- **Booting a real guest** needs a host with `/dev/kvm` and an administrator-supplied
  kernel and root image. The agent is ready for one; this host is not.
- **Snapshots** (A604) need the same, plus a portability tier (ADR 0011): P6-06.
- **Tap devices and network profiles** are declared by the administrator; wiring them
  into the profile is the same shape as the kernel and root image already are.
