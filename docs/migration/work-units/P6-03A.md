# P6-03A replicated control plane with fenced leases

## The problem this solves

Several Aseman replicas serve the API, but some work must happen once: reconciliation,
outbox publication, directory publication, migrations, scheduled settlement. "Once"
cannot be built on a process being alive, because a process can be paused, its clock can
drift, and its database connection can stall — and while any of that is happening it
still believes it holds the lease.

So the lease is not the guarantee. The **fencing token** is: a strictly increasing
number allocated on every acquisition, recorded with every committed effect. A paused
former holder that wakes up carries an old token, and the destination refuses it.

## What was built

| Layer | What |
|---|---|
| `aseman-domain::coordination` | `LeaseName`, `FencingToken`, `Lease`, `SafetyMargin`, `plan_acquisition`, `may_renew`, `standing`, `may_commit`. The rules, with no clock, database, or process in them |
| `aseman-ports::coordination` | `CoordinationPort` (acquire, renew, release, read, `now_millis`) and `FencedDestination` (`last_accepted`, `accept`) |
| `aseman-ports::conformance::coordination` | The A607 kit every provider runs |
| `aseman-storage-postgres::coordination` | The provider: a locked lease row, database time, a token allocated per acquisition, and the fence table |
| `aseman-application::singleton` | `Singleton::run`, which acquires, renews, and yields around the caller's work |
| `apps/aseman-vmm` | Its executor, observer, reconciler, and retention now run only under the lease |

## Decisions worth stating

**The provider's clock, never the caller's.** `now_millis` comes from
`clock_timestamp()` inside the transaction. A replica that cannot reach the provider has
no fresh time and drops its lease rather than assume it still holds one — the
`a_replica_that_cannot_reach_the_provider_gives_up_its_lease` case.

**Stop before expiry, by the safety margin.** The holder stops a full margin before the
lease ends, covering the database round trip and the assumed clock skew. It is therefore
never still working when the provider hands the lease on.

**A release expires the row; it never deletes it.** The row carries the token counter.
The first implementation deleted it, and the conformance kit caught the consequence
immediately: the next holder was granted token 1 again, which would have unfenced every
effect committed before it. A released lease is stored with `expires = acquired` — a
zero-length lease, already over — so the name is free at once and the counter survives.

**Acquisition is atomic against a lease that does not exist yet.** `SELECT ... FOR
UPDATE` locks nothing when there is no row, so the first version granted the same token
to three concurrent replicas; the eight-replica race test caught it. The provider now
inserts first (`ON CONFLICT DO NOTHING` — the primary key serializes the race, exactly
one caller inserts) and only then locks and decides. Both paths use the same domain
function, so the rule stays in one place.

## Verification

| Requirement (ADR 0013) | Evidence |
|---|---|
| Transactionally locked lease row, database time, owner, expiry, increasing token | `PostgresCoordination::acquire`; the A607 kit asserts each |
| Renew and release compare owner and token | `renew` and `release` are scoped to both; the kit asserts a stale release cannot free the new holder's lease |
| A committed effect records and checks the token | `FencedDestination::accept` refuses a lower token in the same statement that records it |
| The holder stops before expiry plus the margin | `standing`, with the domain cases and the application's `a_replica_inside_the_safety_margin_stops_before_the_lease_expires` |
| A paused former holder cannot commit with an old token | the kit's destination case, and the live test's explicit replay |
| Fenced singleton work does not execute twice | `live_singleton_work_happens_on_one_replica_at_a_time`: four replicas, ten passes each, against real PostgreSQL, with an enter/leave log replayed to prove the depth never exceeds one |
| Exactly one replica may hold a lease | `live_coordination_fences_singleton_work`: eight threads acquire simultaneously; exactly one is granted and the losers are told who holds it |
