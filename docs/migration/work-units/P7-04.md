# P7-04 durable realtime and the capsule outbox

## What was built

| Layer | What |
|---|---|
| `aseman-domain::realtime` | The envelope, retention classes, dense per-stream ordering, checkpoint monotonicity, replay bounds, and delivery scope |
| `aseman-ports::realtime` | `EventLog`, `CheckpointStore`, `Outbox` |
| `aseman-ports::conformance::realtime` | The A707 kit every provider runs |
| `aseman-storage-postgres::realtime` | The authoritative log, checkpoints, and outbox on PostgreSQL (ADR 0014) |

## Decisions worth stating

**An event and the change that caused it share a transaction.** The event row and its
outbox row are written together, so an event that exists is always one that will be
published: "it happened" and "it was announced" cannot disagree. The live test asserts
an appended event is in the outbox without a second write.

**Delivery is at least once, and ordering is per stream.** Neither is an apology. No
system can do better than at-least-once across a crash between processing and recording
that it processed; and a global total order would mean a single writer for the whole
node, which nobody needs and everybody would pay for.

**Sequences are dense.** A gap makes a consumer wait forever for an event that is never
coming; a repeat makes replay ambiguous. An append that is not the stream's next is
refused, so a producer learns it raced.

**A checkpoint never moves backwards.** Moving one back replays events the consumer has
already acted on, turning at-least-once into twice-on-purpose.

**A dead worker does not hold the queue.** Claims carry a deadline and use `SKIP
LOCKED`; an expired claim is available again without any cleanup process. Only the
worker that claimed a batch may complete it — another worker completing it would mark
something published that it never published.

**A consumer that has fallen outside retention is told to resync**, rather than served
a silently incomplete stream.

## Verification

| Requirement | Evidence |
|---|---|
| Dense per-stream ordering | domain cases, and `check_event_log` live: a gap and a repeat are both `Conflict` |
| Checkpoints never regress | domain case, and `check_checkpoints` live, which asserts the stored value does not move back after a refusal |
| A claim is exclusive and completable only by its holder | `check_outbox` live |
| A released claim returns to the queue | `check_outbox` live |
| An expired claim returns to the queue | `live_realtime_passes_its_conformance_suites`: a worker claims with a deadline in the past and the next worker takes the same events |
| The outbox is transactional | the same test: an appended event is claimable with no separate enqueue |
| Retention keeps what it promises | the same test: a transient event is purged and a durable one survives |
| Discoverability is not delivery | `discoverability_is_not_delivery` |

## Open, and owned

- **Publishing onward** — the worker that drains the outbox to subscribers — takes the
  fenced lease from P6-03A; the port and the claim semantics are ready for it.
- **The subscription transport** (SSE and WebSocket) is P7-01's.
- **Federation relay** of authorized events is P7-03's transport plus these scopes.
- **Replacing PostgreSQL with an external broker** stays possible: it must pass this
  same suite and migrate offsets through checkpoint capsules (ADR 0014).
