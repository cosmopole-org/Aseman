# P6-04 runtime mappings and enforced egress

## Capabilities are derived, not asserted

`runtime_capabilities(runtime, execution)` reads the generated A505 matrix — the
runtime's own capabilities — and masks off everything Nomad cannot deliver. The first
version of the backend declared a hand-written set that claimed invocation, HTTP
ingress, and files for every runtime. That was a lie for most of them, and a lie a
scheduler acts on.

| Masked off | Why |
|---|---|
| pause, snapshot | Nomad has no allocation-level pause; both belong to the worker agent (ADR 0010, P6-05) |
| exec, terminal | Nomad's exec is a websocket this backend does not speak yet (P6-05) |
| build | an image is built before registration; the scheduler does not build |
| writing files | Nomad's client API reads an allocation directory; it does not write one |

| Narrowed | Why |
|---|---|
| invocation | only for a runtime that also serves HTTP ingress: the ingress is the only way into an allocation the mapping gives |
| execution proofs | only under a runner image, which is what would carry them out |

## Egress is enforced, or the workload is refused

A workload's network policy is deny-by-default (A406): an empty `egress_allow` means it
reaches nothing. Nomad's plain `bridge` hands a workload the whole internet, so a
backend on plain bridge **cannot** honour that policy. It now says so:

- **Deny-by-default on an unrestricted network is refused.** The operator supplies a CNI
  network that enforces it and declares that it does (`{"cni": "...", "denies_egress":
  true}`). Quietly placing the workload anyway — granting the internet to something that
  asked for none, and reporting success — is exactly the dirty path this refuses.
- **Selective allowances are refused too.** Nothing in this mapping can express a
  per-destination allowance, so it is never widened to "everything" nor narrowed to
  "nothing".

The reference network (`contracts/vmm/nomad/aseman-restricted.conflist`) is a CNI bridge
with `ipMasq` off: with no NAT there is no route out, while the gateway — and so the
node's guest API — stays reachable. Ingress still works: the HTTP forwarding test drives
a server inside an allocation on this network.

## Verification

| Requirement | Evidence |
|---|---|
| Capabilities match the runtime and the backend | `runtime_capabilities` is derived from the A505 matrix; `contracts/vmm/nomad/mapping.json` records what is masked and narrowed |
| A deny-by-default workload is refused on plain bridge | `a_workload_that_asks_for_no_egress_is_refused_on_an_unrestricted_network` |
| A selective allowance is refused, not guessed | `a_selective_egress_allowance_is_refused_rather_than_guessed` |
| Egress really is denied | `a_workload_on_the_restricted_network_cannot_reach_the_internet`: the workload tries to reach an external address and reports `EGRESS-DENIED`. The same image run unrestricted reports `EGRESS-REACHED`, so the test can fail |
| Ingress still works on the restricted network | `a_workload_runs_serves_http_and_is_purged` and the A504 conformance run, both on `cni/aseman-restricted` |

## Open, and owned

- **Runner images** for javascript, wasm, elpian, and elpify are declared per runtime by
  the operator; the mapping never invents one. The image itself — a hardened OCI runner
  that fetches the artifact with the workload credential and executes it — is built in
  Phase 9 packaging (A007).
- **QEMU** is mapped in the contract; the driver needs a bootable artifact, which no
  current runtime produces.
- **Firecracker** is P6-05: an unprivileged runner task plus the worker agent.
- **Per-destination egress allowances** need a policy the network can be told about, and
  stay refused until there is one.
