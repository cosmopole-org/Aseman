# P5-03 the A504 backend contract and the native backend

## Requirement and ownership

P5-03 extracts the integrated VMM into `modules/vmm-backend/native-legacy` behind a
versioned backend contract (A504), "preserving valid runtime behavior while deleting
its access to node internals, storage handles, shell actions, finance, and global
application state" (plan 04).

## Delivered

- **A504** (`contracts/vmm/backend/v1/backend.proto`): `Describe`, `Step`,
  `ObserveAll`, `Run`, `ForwardHttp`, `PutFile`, `GetFile`, `Endpoints`, `Usage`,
  `Logs`, `Verify`. Every request carries the module `RequestMetadata` (request ID,
  trace, deadline) and every response a structured `ModuleError`. Workloads and
  data-plane payloads are the A501 JSON, so one schema serves both hops.
- **Transport** (`modules/vmm-backend-grpc`): a server for any `VmmBackend`, and the
  VMM service's client. Plaintext A504 is refused off the host.
- **Conformance kit** (`tests/contracts/vmm-backend`): one suite every backend passes.
- **The native backend** (`modules/vmm-backend/native-legacy`):
  - links `caspar-vm-plugins`; the node no longer does;
  - implements the SDK's `VmHost` over the guest API (P5-04) — a plugin's every call
    goes out as the workload it runs, and there is no other path to the node;
  - fetches each program artifact with that workload's credential and verifies its
    digest before use; builds a build-on-deploy runtime before its first start;
  - keeps instances, logs, and usage counters of its own, and answers A504 from them;
  - owns the docker-host gateway, moved out of the node with its protocol tests.

## Verification

| Check | Evidence |
|---|---|
| A504 is transparent: the same suite passes directly and over gRPC, errors keep their meaning | `aseman-vmm-backend-grpc` `the_reference_backend_conforms`, `a504_is_transparent_to_the_backend` |
| Real programs run: `counter.js` on the JavaScript runtime, its state calls signed as its workload | `live_native` |
| Docker parity on a real daemon: build, run, HTTP into the container, file copy, exec, stop, delete | `live_docker` |
| A borrowed credential and a mismatched artifact digest are refused | `live_native` |
| Capability refusals are not degraded | `live_native`, application `vmm` tests |

## Rollback

The backend is a separate process. Stopping it leaves the node's records untouched;
the VMM reports its workloads lost and reconciles when it returns (`system` test).
