# P3-04 non-core storage-class work record

## Requirement and artifacts

P3-04 implements A307 under ADR 0006, ADR 0007, and ADR 0014. RL-005 owns the
legacy RocksDB/QuestDB replacement, while RL-008 and RL-011 own later realtime and
finance implementation removal. This slice installs native storage contracts and
physical mappings; it does not cut over any current authority or delete legacy data.

## Implemented

- A closed thirteen-kind registry and logical schemas covering telemetry workload/node
  observations and build logs, audit events, wallets, ledger entries, pricing policies, finalized usage,
  transactional outbox messages, realtime events, subscriptions, consumer offsets, and
  dead letters.
- Explicit minimum consistency, capability, ownership, mutation, retention, uniqueness,
  and range-query semantics. Finance and outbox reject eventual fallback; audit and event
  streams require append-linearizable, verifiable behavior; telemetry alone may be
  eventual and cannot authorize decisions.
- Generated native PostgreSQL schemas and typed tables for all five storage classes.
  Canonical CBOR preserves portable envelopes while typed columns, foreign keys, checks,
  partial uniqueness, B-tree/BRIN indexes, and class-specific schemas enforce physical
  behavior. There is no JSONB entity bucket or universal payload table.
- Database-enforced immutability for audit events, ledger entries, pricing versions,
  finalized usage records, and realtime events. Per-stream/event idempotency indexes
  reject duplicate ordered inserts.
- Idempotent installation with the core migration. A disposable PostgreSQL 16 test runs
  both migrations twice, executes capsule-provider conformance, verifies all thirteen
  tables, proves append-only mutation fails with SQLSTATE `55000`, and proves duplicate
  audit sequence fails with SQLSTATE `23505`.

## Migration and rollback

The new schemas are additive. P3-05 exports legacy records as canonical capsules and
P3-06 compares and cuts over bindings only after class-specific semantic checks pass.
Rollback restores the old binding and leaves the new schemas intact for reconciliation;
acknowledged durable events, audit records, and financial records are never discarded.
Physical schema removal remains forbidden until each owning ledger row passes replacement,
rollback-window, and deletion gates.

## Activation boundary

This work accepts A307 storage semantics and the native mapping, not the later business
services. P7 owns authorization, delivery, replay, and retention workers for realtime;
P8 owns pricing, double-entry, settlement, and consensus semantics. Production activation
also requires separate migration/runtime database roles and the relevant provider
conformance suites; a superuser connection used by disposable tests is not a deployment
permission model.
