# P3-03 creature-isolated guest database work record

## Requirement and artifacts

P3-03 implements the storage-owned portion of A306 under ADR 0001, ADR 0006, and
ADR 0007. RL-006 owns replacement and deletion. The exact signed workload proof and
authoritative workload-to-program-to-creature resolution remain P4-04/A401/A405; this
work does not expose an unauthenticated guest edge or activate a legacy replacement.

## Implemented

- One deterministic, provider-selected PostgreSQL database and one dedicated `NOLOGIN`,
  unprivileged role per creature binding generation. Public database and schema access is
  revoked, and the proxy is the only login role allowed to assume creature roles.
- Disabled-first provisioning, explicit enable/disable, connection termination, retained
  generations, and pool retirement. Workloads receive no provider credential and no API
  accepts a caller-selected provider, database, namespace, role, or creature as routing
  authority.
- Bounded lazy pools keyed by the trusted provider/database/role/generation binding.
  Checkout, transaction, cancellation/error, commit, and return paths reset and verify
  session user, current role, current database, settings, and temporary state.
- A closed portable multi-table schema model with typed columns/defaults, relationships,
  indexes, destructive-change approval, protected `_aseman_*` capsule metadata, quotas,
  safe identifiers, and no raw SQL or universal `guest_capsules` table.
- Revision-fenced schema commands. PostgreSQL serializes each command against a
  provider-private catalog, executes DDL with `SET LOCAL ROLE`, appends the portable
  mutation to an inaccessible change journal, and advances the catalog revision in the
  same transaction.
- A306 isolation rules for binding-aware pools, queries, cursors, caches, events, and
  exports, plus the signed proxy fields/checks whose concrete encoding and implementation
  are owned by A401/P4-04.
- A disposable PostgreSQL 16 adversarial test covering two databases and roles,
  multi-table foreign-key schemas, cross-catalog absence, protected-catalog denial,
  direct-login denial, stale-revision rollback, error rollback, role contamination
  detection and cleanup, pool capacity, disablement, and retirement.

## Migration and rollback

Provisioning is additive and disabled by default. P3-05 imports portable schemas and
records into the disabled generation; P3-06 and P4-04 may enable it only after semantic,
isolation, and authentication gates pass. Rollback atomically restores the prior trusted
binding generation, disables and drains the target, terminates its sessions, retires its
pool, and retains the database for comparison. Database and role deletion remains
forbidden until RL-006 replacement and deletion gates pass.

## Activation boundary

The provider substrate is accepted, but it is not a production guest gateway. P4-04 must
verify canonical public-key signatures, audience, freshness, nonce/replay, key epoch, and
revocation, then resolve workload -> program -> creature -> trusted binding server-side.
Until that boundary exists, no VM path is authorized to call this provider directly.
