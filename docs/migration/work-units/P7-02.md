# P7-02 descriptor records and the envelope guard

## What was built

| Layer | What |
|---|---|
| `aseman-ports::federation` | `Directory` (own node, node and workload descriptors, recording each) and `EnvelopeGuard` (nonces and answered requests) |
| `aseman-federation-http::PostgresFederation` | Both, on PostgreSQL, with the forward-only guards in the SQL itself |

## Two different things, recorded separately

A **nonce** says "this exact envelope has been seen". A **request id** says "this
request has been answered, and here is the answer". Conflating them would make a
legitimate retry look like a replay, or a replay look like a retry — the first breaks
reliability, the second breaks security.

So a repeated nonce is refused as a replay, while a repeated `request_id` is answered
from the record without executing anything a second time. **The first answer stands**: a
racing retry must not replace what a caller may already have received.

Nonces are scoped per source node, so two peers choosing the same nonce value do not
collide.

## Forward-only, in the SQL

The `WHERE` clause on each upsert is the guard: a node descriptor whose sequence does
not rise, or a workload descriptor whose revision does not rise, updates no row and the
caller is told `Conflict`. A replayed older descriptor therefore cannot un-rotate a key
or un-revoke an epoch, and a refused descriptor does not roll the cache back.

A descriptor that names its own key epoch among its revoked epochs is refused outright:
a node cannot publish keys it has itself revoked.

## A cache that knows it is a cache

An expired descriptor is not served. The home node is authoritative; this is only what
this node has learned. A node with no descriptor of its own answers `NotFound` rather
than an empty cache — that is a configuration failure and should look like one.

Purging drops nonces and answers whose envelopes could no longer be accepted anyway, so
the memory cost of replay protection is bounded by the 60-second envelope lifetime.

## Verification

`live_federation_records_only_move_forward`, on PostgreSQL 16: an older and an equal
sequence are both refused and the cache does not move back; a higher one is accepted; a
self-revoked epoch is denied; an expired descriptor is not served; workload revisions
move forward; a repeated nonce is a replay while another source may use the same value;
a recorded answer is returned and a second answer does not replace it; and purging drops
both kinds of record so a long-expired nonce may be used again.
