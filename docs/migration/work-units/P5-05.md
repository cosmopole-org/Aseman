# P5-05 logs, events, usage, restart reconciliation, handoff adoption, and parity

## Delivered

- **Logs**: the backend keeps each workload's output (a bounded ring per instance,
  fed by the runtime's log packets) and serves it over A504; the VMM streams it as
  SSE with `Last-Event-ID` resumption.
- **Events**: every observation, operation, and deletion is appended to the VMM's
  ordered log, owner-scoped, with `resync` when a reader's position has aged out.
- **Usage**: invocation counts and execution time per workload, cumulative with a
  sequence for metering (P8).
- **Restart reconciliation**: the observer marks an instance the backend no longer
  reports `lost`; reconciliation restarts it at the desired generation. Proven by
  killing the backend process mid-test.
- **Terminal**: the contract carries it, no native runtime offers it (the legacy
  "terminal" was a log subscription, which `streamWorkloadLogs?follow=true` serves),
  so the route answers `unsupported_operation`.
- **Handoff adoption (ADR 0022)** (`aseman-storage-legacy::vmhandoff`,
  `aseman-node vmm-handoff`):
  - `plan` lists every legacy `VmInstance` with its runtime and external handles
    (containers, Modal app/image/volume/sandbox), with a digest;
  - `apply` refuses decisions made for a different plan, requires one decision per
    instance and per handle, runs every adopted instance as a workload, and only then
    removes the decided observed records. A stopped instance's container must be
    released, never kept: nothing would own it. Kept handles (Modal user data) stay
    for their runtime module (P6-06).
- **Parity matrix (A505)**: 22 of the 27 A006 operations verified, 5 open with
  reasons (Modal restore needs an account; elpify proof verification needs a proof
  fixture; the gateway's source-IP identification needs a container speaking the
  gateway protocol; two plan-request helpers are unused).
