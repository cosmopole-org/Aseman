# P5-02 provider-neutral VMM service and node client

## Requirement and ownership

P5-02 builds the provider-neutral part of `aseman-vmm`, and the client the node uses
to reach it:
- the common authentication, idempotency, operation tracking, reconciliation, events,
  and API semantics (plan 04);
- the node's client, which replaces `VmmPort`.

The infrastructure work happens behind the backend port (A504), which P5-03 fills
with the native backend and its protobuf contract.

## Delivered

- **Domain** (`aseman-domain::vmm`):
  - the stored records: workload, operation, event;
  - the workload spec, labels, observation, usage, log, and endpoint types, which
    `aseman-contracts::vmm` re-exports as its wire types;
  - the closed failure code set (`VmmFailure`, A501 `ProblemCode`), including
    `already_exists`;
  - `Generation` refuses 0 when deserialized, so an invalid generation never
    crosses an edge.
- **Ports** (`aseman-ports::vmm`):
  - the service stores, all scoped by the calling node (`owner`): workloads with
    resource-version compare-and-set, operations with state compare-and-set,
    idempotency keys, and an ordered event log with resync;
  - `VmmBackend` (A504 in Rust);
  - `VmmClient`, the node side.
- **Use cases** (`aseman-application::vmm::VmmService`):
  - **Create:** checks runtime capabilities; declared ingress on a runtime without
    ingress is refused.
  - **Lifecycle commands:** freshness under the node's generation (apply, replay the
    same operation, or `stale_generation` naming the current generation), then
    `If-Match`, the desired transition, and the capability.
  - **Spec updates, restore, and data-plane operations:** invocations, chain
    invocations, exec, builds, and snapshots.
  - **The executor:**
    - one attempt per operation;
    - lifecycle operations stay running until they converge;
    - retryable backend failures are retried;
    - superseded generations fail;
    - deadlines fail the operation;
    - a result that arrives after a cancellation is discarded.
  - **Observation:** forward-only; an instance the backend stops reporting becomes
    `lost`; an instance no workload desires is left alone.
  - **Reconciliation:** opens one operation per drifted workload.
- **Stores**:
  - `PostgresVmmStore` in its own `aseman_vmm` schema
    (`migrations/vmm/0001_vmm.sql`). Event sequences come from a locked counter, so
    commit order is sequence order.
  - The in-memory reference stores and the scripted reference backend live in
    `aseman_ports::conformance::vmm`.
- **Transport** (`modules/vmm-http`):
  - **Server:**
    - rustls mutual TLS; a client is admitted only by the SHA-256 of its leaf
      certificate, and that fingerprint names the owner;
    - `Idempotency-Key` on every mutation, with digest-bound replay, a
      reuse refusal, and a takeover of abandoned claims;
    - `If-Match` and `ETag`, `Aseman-Deadline`, and `X-Request-Id`;
    - RFC 9457 problems, a body limit, cursor pages;
    - SSE events and logs with `Last-Event-ID` and `resync`;
    - a separate plain health router.
  - **Client** (`HttpVmmClient`): blocking mutual TLS with https only. It retries
    under the same key and maps problems to port errors.
- **Node use case:**
  - `SetDesiredWorkloadState` records the desired state, then commands the VMM with
    the key `desired-{workload}-{generation}`, so a retry after a crash is
    deduplicated. `VmmPort` is deleted.
  - Config: `VmmClientConfig` (https and mutual TLS only) replaces the unused
    plain-HTTP `ASEMAN_VMM_ENDPOINT` default. `VmmServiceConfig` covers the
    service.

## Remaining for later work units

- **P5-03:** the `apps/aseman-vmm` executable, which composes the service with the
  A504 backend client, runs the executor, observer, reconciler, and idempotency and
  event purges on `reconcile_interval_millis`, and serves the health router. The
  node composition installs `HttpVmmClient` when `ASEMAN_VMM_ENDPOINT` is set, and
  operations move to it one lifecycle operation at a time.
- **P5-05:** trace propagation to the backend (it needs A504 metadata), and terminal
  attachment. Until then the terminal route answers `unsupported_operation`, or
  `unavailable` for a runtime that declares a terminal.

## Rollback

The node still uses the embedded VMM. Nothing routes to the service yet, so rollback
means not configuring `ASEMAN_VMM_ENDPOINT`.
